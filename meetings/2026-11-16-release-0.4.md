# Release 0.4.0 and the next milestone

0.4.0 was released on 2026-11-16, closing all seven entry conditions within budget. **Decide** what 0.5 holds and its budget. 0.5 *Agent interface* is planned with six features; two of them overlap existing commands, so merging them is proposed first.

## 1. Released

* v0.4.0 (GitHub release with the package). Entry conditions: #64 product data only, #54 use by LLM agents (US-12, README), #36 block-style `plm new`, #35 enum values in findings, #33 retained requirements in allocation, #9 confirm a run against a changed system under test, #20 project link types and `report coverage --link`. It also ships #26–#28 type files (breaking; the CHANGELOG has the conversion table) and #19 parameter citations.
* Budget 3 windows; the four reviewed features took one window. `scripts/check.sh` passes (5 of 5 checks).
* Open findings: none. The reviewer caught two bugs before merge (#33 lost allocation through lower requirements; #20 ignored a type's `base`), and both were fixed.
* Word limits after the raise of #71: `documents/` 5000/5000, `src/`+`test/` 5316/5340. 0.5 adds commands, so the limits go up again (chief engineer, #71).
* For the owner: the shift's guard blocks closing GitHub milestone *0.4* (the API is not allowed). Please close it.

## 2. Next milestone: 0.5 Agent interface

Planned: #58 schema as JSON, #56 context view, #63 trace queries, #57 atomic changes with dry run, #55 MCP server, #60 CI integration. Each adds a command or a new interface, so each is a big feature and gets a feature review before it is built.

**Decision 1: scope.**
* A (recommended): four features. Fold #56 into #63, so that `plm trace <ID>` at depth 1 is the context view (one graph walk, not two commands). Turn #60 into a README section with a generic CI script on existing commands (`validate`, `impact`, `suspects`), not a shipped action tied to one CI service (`CLAUDE.md`, Scope). Entry conditions: #58, #63 (with #56), #57, #55, and #60 as documentation.
* B: all six as planned. About 1½ windows more, with two overlapping views of an item.
* C: A without #55 (MCP), moved to 0.6: the MCP server only wraps commands, so it can wait until #57 and #63 settle.

**Decision 2: budget.** 0.4 used 1 window for four reviewed features of about ⅓ window each. 0.5 holds larger features (new commands; #55 a server).
* Recommended: 4 windows for A (3 for C, 5 for B).

The feature review for 0.5 is prepared next, then the features are built in the order #58, #63, #57, #55, #60.
