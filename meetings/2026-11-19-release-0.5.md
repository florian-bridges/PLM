### 3.1 #29 Ports and connections

**Need.** Where subsystems of different disciplines meet (a bus, a power line, a joint), nothing records what was agreed or flags the other side when one side changes. Most of it works by configuration today: a type file with `folder: ports`, a `connects` link in `plm.yaml` (CO-02.9); an `icd.yaml` change changes the port's version (TE-01), so the connection's link goes suspect (TE-03.1). Missing: `implements` to a connection (CO-02.6 limits it to requirements; CO-02.9 forbids redeclaring a built-in link) and the schema check of `icd.yaml` (owner decisions of 2026-11-14, #29).

**Proposal.** CO-02.5 gains `port` `PORT-` `ports` and `connection` `CON-` `connections`; CO-02.6 gains `connects` from connection to port and `implements` also to connection. New **CO-02.10:** "A type file may hold `files: {<name>: <JSON Schema>}`; the core shall validate each named YAML file in an item's folder against it, as CO-02.1, reporting `schema` findings with that file's line." Connection-defining fields (pin pairs, baud rate) go on types with `base: connection` (CO-02.8, unchanged). Touches `src/schemas.ts:20`, `:21`, `:30`; `src/validate.ts:44`, `:84`; README, `architecture.md`.

**Options.** **A (recommended)** as above: about +90 `documents/`, +110 `src/`+`test/`; 1 window. `files` serves any type and any structured artifact, and leaves room for later per-type `checks`. **B** configuration only plus `files`, a README example instead of built-in types: +45/+60, ½ window; #31 cannot recognise ports, connections cannot be implemented. **C** built-in types only, `icd.yaml` unchecked: +30/+40, ½ window; contradicts the owner's decision.

**Architecture:** none (data format only extended). Two notes: the core reads an artifact's content for the first time; `ports` and `connections` become reserved home folders (an existing folder of that name gives `misplaced` findings).

### 3.2 #30 Directed port types

**Need.** On some interfaces direction matters (one sender, several receivers), so it is set per port type.

**Proposal.** No new key: a directed port type declares `fields: {role: {enum: [sender, receiver]}}, required: [role]`. CO-02.8 already gives the rest (missing role a warning on `draft`, else an error, CO-02.4; undeclared `role` rejected, `src/validate.ts:19`; `new` writes it from the template). Only the `senders` finding is new.

**Options.** **A (recommended)** fold into #31: about +10 words, 0 windows. **B** a `directed` key and a new CO-02.11, as the issue says: +40/+60, ½ window, duplicates `fields`/`required`. **C** no `senders` check: direction is a field only.

### 3.3 #31 `plm report connections` (with #30)

**Need.** The interface owner needs open ports and connections that do not fit together, kept out of `validate`, `suspects` and `report coverage`. `report coverage --link connects` already lists open ports via `unreached` (`src/links.ts:166`, TE-06.5).

**Proposal.** New **TE-07** (CR-10; US-2): "The engine shall report open ports and connections whose ports do not fit together." New **TE-07.1:** "For the repository or a subtree it shall list `open` (a port no `connects` link reaches), `few` (a connection with fewer than two ports), `mixed` (ports of more than one type) and `senders` (ports with a `role` but not exactly one `sender`); exit 1 if any; JSON rows `{code, item: {id, title}, detail}`." CL-01.1 and CL-05.3 gain `report connections [<item>]`. Touches `src/cli.ts:192`, reuses `src/links.ts:166`.

**Options.** **A (recommended)** as above: +80/+130, ¾ window. **B** drop it: `open` exists via `--link connects`; the rest waits for per-type checks. **C** findings as `validate` warnings: +40/+70, ½ window; contradicts the need.

## Reviewer findings

* Claims, refs and unused IDs confirmed; the draft follows all four #29 owner decisions. Drop CL-01.7 from the shared change (no draft uses it).
* Traces: CR-10 must also cite US-2; no new requirement cites CR-01, so drop "CR-01 gains 'and interfaces'" or let CO-02 cite it.
* CO-02.8 lists the only keys a type file may hold, so it must gain `files`, and say whether `base` inherits it.
* Architecture note: `artifacts()` skips home folders (`src/repo.ts:176-181`), so an existing artifact subfolder named `ports` or `connections` stops being an artifact, its item's version changes and its links go suspect: a small breaking data-format change, to be named in the CHANGELOG.
* #31: write the checks as TE-06.6 under TE-06 (unreached items by link type) instead of a new TE-07, about −20 words; keep `open` as a call to `unreached`.
* `senders` reserves the field `role` with values `sender`/`receiver`; TE-06.6 must name that convention. `mixed` assumes both ends share one port type, which may not fit plug/socket pairs: **owner question**, keep `mixed` or drop it (about −8 words).
* Verdicts: #29 A, go with the CO-02.8 and folder-note fixes; #30 A (folded into #31); #31 A as TE-06.6, `mixed` decided by the owner; budget 2½ windows holds.
