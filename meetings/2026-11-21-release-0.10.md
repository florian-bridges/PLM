**Options.** **A (recommended)** extend `impact`, no new command: **TE-05.4** "`impact` shall also list, per item, the `uses` entries added, removed, or changed in `quantity`, `ref` or `when` between base and head." About +25 `documents/`, +150 `src/`+`test/`; ¾ window. **A+** A plus **VS-03.6**, a command opening `impact` since a picked ref in the Markdown preview: +25 `documents/`, +60 `extension/`, and a Markdown output of `impact`; the reviewer advises against it (wrong parent VS-03; terminal and agents cover US-10). **B** a new `plm diff` command and core function with a tree view: about +60/+300/+200, 1½ windows; duplicates `impact`'s base/head walk. **C** no-go: `git diff` of the YAML files.

### Reviewer

* **3.1 TE-05.4:** "assembly" names an item kind (scope): write "per item". "Changed" is vague: name the keys (`quantity`, `ref`, `when`). Need cites US-9 (reviews and findings); US-10 alone fits, as for TE-05. Overlap with TE-05.1 is small: it already lists the item whose `item.yaml` changed and the items above it, but not the entries.
* **3.1 VS-03.6:** propose drop (about −25 `documents/`, −60 `extension/`). `impact` prints text, not Markdown, so the preview needs a Markdown output nothing states. VS-03 is about an item's requirements document, not change impact, so it is the wrong parent. `plm impact <range>` in a terminal or agent already covers US-10.
* **3.2 CL-01.9:** unclear whether it counts the whole repository or the item's subtree (CL-01.8 takes `[<item>]`): say "within the printed subtree". "Validation findings by kind": use the error codes `validate` already reports (e.g. `ambiguous-use`) and reuse its function, not a second count. Test runs are already in CL-01.8 (TE-06.1); drop them from the Need.
* **3.3 VS-07:** has no parent. Component requirements must cite a CR and a US (CLAUDE.md), and "owner interview" is neither. The nearest are CR-05 and US-2, but no scenario asks for a whole-product picture. Add a scenario clause first, or choose C.
* **3.3 VS-07.1:** a +400-word webview goes against VS-03.5's rationale (reuse a VS Code renderer rather than a second one); the document webview was removed in 0.10 for that reason. "Coloured by state" restates TE-03.1, and "without dependencies" is a design choice, not a requirement. Option B's data already exists in `show --down/--up` JSON (CL-01.5); a graph format there would cost less than a new `report graph`.
* **Budget:** `src/`+`test/` has 1 word of margin and `extension/` 16. 3.1A plus 3.2A need about +230, and VS-07.1 +400. Limits are raised only after cuts, so plan each feature with a cut beside it (e.g. dropping VS-03.6).
